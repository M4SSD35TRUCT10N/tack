# ADR 0001 — Eröffnung der 0.8-Serie / Open the 0.8 series

**Status:** angenommen / accepted  
**Serie:** v0.8.0-dev  
**Typ:** Architektur- und Versionsentscheidung / architecture and versioning decision

---

## Deutsch

### Kontext

`tack` hat in der 0.7-Serie mehrere tragende Grundlagen aufgebaut: fail-fast-Härtung, data-only-Konfiguration per `tack.ini`, optionales `tackfile.c`, dokumentierte Layering-Regeln sowie erste Doku-/BOM-/SBOM-Funktionen.

Gleichzeitig zeigt die Nutzung in realeren Projekten, dass zwei Themen jetzt eine eigene Entwicklungslinie rechtfertigen:

1. **Spezifikationsdisziplin:** Änderungen sollen vor der Implementierung nachvollziehbar beschrieben werden.
2. **Compiler-/Toolchain-Politik:** die bisherigen Built-ins sind funktional, aber in Teilen noch zu stark an stillschweigende TCC-Nähe gekoppelt.

### Entscheidung

Mit diesem Commit wird bewusst die **0.8-Serie** eröffnet.

Das bedeutet in diesem ersten Schritt:

- `docs/` wird als offizieller Ort für Spezifikationen und Architekturentscheidungen eingeführt.
- Root-Dokumente verweisen künftig ausdrücklich auf diese ergänzende Nachweis-Schicht.
- Die **0.7.25-Implementierung bleibt die aktuelle Feature-Basis**, solange noch keine 0.8-Codeänderung eingecheckt wurde.
- Produktions-C-Code und Tests bleiben in diesem Schritt unverändert.

### Begründung

Diese Änderung ist größer als ein gewöhnlicher 0.7.x-Doku-Patch, weil sie den künftigen Änderungsprozess selbst festlegt:

- mehr explizite Vorab-Spezifikation,
- klarere Trennung zwischen Produktdoku und Architektur-/Entscheidungsdoku,
- Vorbereitung einer **INI-first**-Politik für spätere Toolchain- und CI-Erweiterungen,
- saubere Versionserzählung ohne stillschweigende Verschiebung der Semantik.

### Folgen

- 0.7.x dient ab jetzt nur noch als stabile Referenz-/Bugfix-Basis.
- Neue Grundsatzänderungen laufen über die 0.8-Serie.
- `README.md`, `FAQ.md`, `ROADMAP.md` und `RELEASENOTES.md` müssen weiterhin bilingual und aktuell bleiben.
- `docs/specs/` und `docs/adr/` werden ab jetzt Teil des normalen Review- und Dokumentationspfads.

## English

### Context

During the 0.7 series, `tack` built several core foundations: fail-fast hardening, data-only configuration through `tack.ini`, optional `tackfile.c`, documented layering rules, plus early doc/BOM/SBOM functionality.

At the same time, usage in more realistic projects now shows that two topics justify a dedicated new development line:

1. **Specification discipline:** changes should be described in a traceable way before implementation.
2. **Compiler/toolchain policy:** the current built-ins are functional, but parts of them still lean too much on implicit TCC-centric assumptions.

### Decision

This commit deliberately opens the **0.8 series**.

In this first step, that means:

- `docs/` becomes the official home for specifications and architecture decisions.
- Root documents will explicitly link to this supporting evidence layer.
- The **v0.7.25 implementation remains the current feature baseline** until the first 0.8 code change lands.
- Production C code and tests remain untouched in this step.

### Rationale

This is larger than a normal 0.7.x documentation patch because it defines the future change process itself:

- more explicit up-front specification,
- a clearer split between product docs and architecture/decision docs,
- preparation for an **INI-first** policy for later toolchain and CI extensions,
- a clean version story without silently shifting semantics.

### Consequences

- 0.7.x now serves mainly as the stable reference/bugfix line.
- New foundational work moves through the 0.8 series.
- `README.md`, `FAQ.md`, `ROADMAP.md`, and `RELEASENOTES.md` must remain bilingual and current.
- `docs/specs/` and `docs/adr/` become part of the normal review and documentation path.
