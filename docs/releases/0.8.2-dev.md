# tack 0.8.2-dev / compiler by target profile

**State / Status:** Implementation candidate. NOT RELEASED / nicht freigegeben.

## German / Deutsch

Änderung: `[target "NAME".debug]` und `[target "NAME".release]` erlauben `compiler` und `compiler_policy`. Priorität: `TACK_CC`, Targetprofil, Projekt, Built-in. `tack test` wählt die Compiler- und CFLAG-Policy des betroffenen Targets; `tack doctor release --target NAME` zeigt die wirksame Auswahl. Der `tack`-Scope bleibt Build/Toolchain, nicht Agentenorchestrierung.

**Durchgeführt:** Sichtprüfung der geänderten Projektquellen und Syntaxprüfung von `src/tack.c` mit GCC/C89 ohne Programmausführung. **Nicht durchgeführt:** Regressionstests, Compiler-Matrix, Windows-, TDM-GCC- und TinyCC-Abnahme. Die neue Testquelle `tests/compiler_target_profile_selection_test.c` wurde erstellt, aber nicht ausgeführt. Die unveränderte Cache-Semantik verlangt `--rebuild` bei Compilerwechsel innerhalb desselben Profils.

## English

Added per-target/profile `compiler` and `compiler_policy` selection, test compiler/CFLAGS alignment, and `doctor release --target NAME`. Priority: environment, target profile, project, built-in. Single-file C89 syntax validation was performed; regression tests and Windows/TinyCC/GCC/Clang matrix were NOT run. Explicit cache limitation: use `--rebuild` when switching the compiler within a profile.

- `tack --config .\tack.ini test release --ci --rebuild -j 1`
