### Windows CMD: Build, Ratchet, GCC Release, TCC Debug, GCC/gcov, HWM, Dokumentation

Diese Zeilen sind vollständige, unabhängige CMD-Befehle ohne `^`-Fortsetzung. Auf `C:\Projects\tack` den **Inhalt** des RC0.7-Archivs über die Arbeitsdateien übernehmen; `.git` **niemals** überschreiben. Die `BUILD_RC`, `RATCHET_RC`, `GCC_RELEASE_RC`, `TCC_DEBUG_RC` und `DOC_RC` müssen 0 sein. Eine valide neue Coverage-Messung kann mit Exit 2 `BLOCKED` enden, wenn die HWM noch nicht angenommen wurde; der Test-Summary muss zugleich 0 funktionale Fehler ausweisen.

```bat
cd /d C:\Projects\tack
git status --short --branch
git branch --show-current
git diff --check
set "TACK_CC=gcc"
tack --config .\tack.ini build release --target app --rebuild -j 1
echo BUILD_RC=%ERRORLEVEL%
.\build\app\release\bin\tack.exe --version
.\build\app\release\bin\tack.exe --config .\tack.ini ratchet tests
echo RATCHET_RC=%ERRORLEVEL%
.\build\app\release\bin\tack.exe --config .\tack.ini test release --ci --rebuild -j 1
echo GCC_RELEASE_RC=%ERRORLEVEL%
set "TACK_CC=tcc"
.\build\app\release\bin\tack.exe --config .\tack.ini test debug --ci --rebuild -j 1
echo TCC_DEBUG_RC=%ERRORLEVEL%
set "TACK_CC=gcc"
.\build\app\release\bin\tack.exe --config .\tack.ini test coverage --ci --rebuild -j 1
echo GCC_COVERAGE_RC=%ERRORLEVEL%
type coverage\current.txt
.\build\app\release\bin\tack.exe --config .\tack.ini coverage check
echo HWM_CHECK_RC=%ERRORLEVEL%
.\build\app\release\bin\tack.exe --config .\tack.ini doc --strict
echo DOC_RC=%ERRORLEVEL%
```

### Windows CMD: externer Formatter E2E, echte Dateiänderung, kein Schaden am Original bei `--check`

Die vorhandene isolierte RC0.3-Fixture `build\fmt-e2e v085\fmt.ini` wird verwendet; falls sie nicht mehr existiert, die unter `docs/guides/formatter-external-validation.md` dokumentierte Konfiguration erneut nur im `build`-Verzeichnis anlegen. Keine Projektquellen formatieren.

```bat
cd /d C:\Projects\tack
where clang-format
clang-format --version
set "TACK_FMT_EXE=C:\Projects\tack\build\app\release\bin\tack.exe"
cd /d "C:\Projects\tack\build\fmt-e2e v085"
echo int main(void){return 0;}>"src\with spaces.c"
copy /y /b "src\with spaces.c" "before-check.c"
"%TACK_FMT_EXE%" --config .\fmt.ini fmt --list --strict -- "src\with spaces.c"
echo LIST_RC=%ERRORLEVEL%
"%TACK_FMT_EXE%" --config .\fmt.ini fmt --check --strict -- "src\with spaces.c"
echo CHECK_BEFORE_RC=%ERRORLEVEL%
fc /b "src\with spaces.c" "before-check.c"
echo UNCHANGED_FC_RC=%ERRORLEVEL%
"%TACK_FMT_EXE%" --config .\fmt.ini fmt --strict -- "src\with spaces.c"
echo FORMAT_RC=%ERRORLEVEL%
fc /b "src\with spaces.c" "before-check.c"
echo CHANGED_FC_RC=%ERRORLEVEL%
"%TACK_FMT_EXE%" --config .\fmt.ini fmt --check --strict -- "src\with spaces.c"
echo CHECK_AFTER_RC=%ERRORLEVEL%
type "src\with spaces.c"
cd /d C:\Projects\tack
git status --short --branch
git remote -v
git fetch origin
echo FETCH_RC=%ERRORLEVEL%
git status --short --branch
```

Die `FAIL`-/`BLOCKED`-Zeilen innerhalb des bestandenen `coverage_ratchet_test` sind absichtliche Negativprüfungen, keine funktionalen Testfehler.
